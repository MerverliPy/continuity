# Continuity and Superpowers boundary

Continuity supplies preserved project truth, evidence states, authority scope, lifecycle status, readiness, and one exact next action. It remains useful as a complete portable result when Superpowers is absent.

Superpowers may perform design, planning, building, testing, debugging, review, and verification only after Continuity gates pass and only within the recorded authorization boundary. A companion recommendation is workflow routing, never an expansion of authority.

## Readiness routing

- `Ready`: the exact next action is authorized, integrity and canonical authority pass, and no material conflict remains. Recommend only the directly relevant companion skill or stage.
- `Conditional`: the next action is authorized and every remaining condition has cited proof that it cannot affect that action. Carry every condition into the companion brief.
- `Blocked`: return a useful Continuity blocker report, omit execution-stage recommendations, and do not invoke or route planning, implementation, testing, review, deployment, or other mutation.

If authority, identity, or material-conflict evidence is incomplete, return to Continuity reconciliation. If the selected project is uncertain, return to project selection. If Superpowers is unavailable, state that fact without weakening or withholding the Continuity result.
